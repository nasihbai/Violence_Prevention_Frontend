# i18n (vue-i18n) Rules

## The cardinal rule
**Every new key MUST be added to every file in `src/locales/`.** Missing locales fall back silently, which means broken UI ships without errors.

## Workflow when adding a key
1. List the locale files: `ls src/locales/`
2. Choose the namespace (e.g., `alerts.list.title`).
3. Add the key + translation to every locale file.
4. Use it: `{{ t('alerts.list.title') }}` in template or `t('alerts.list.title')` in `<script setup>` via `const { t } = useI18n()`.
5. Smoke test by switching the active locale in dev and confirming the key resolves.

## What counts as user-visible
- Template text content (`<h1>Hello</h1>`)
- Attributes: `alt`, `aria-label`, `title`, `placeholder`, `aria-description`
- Toast/sonner messages
- Validation messages from `@vuelidate/validators` — use i18n via a helper
- Date format strings (use `vue-i18n` date formatting, not hardcoded patterns)

## What is exempt
- Console logs (developer-facing)
- Error messages thrown to internal `try/catch` blocks (not surfaced to users)
- Test fixtures
- CLI / build script output

## Anti-patterns
- ❌ Adding a key to one locale "for now"
- ❌ Using template literals to build i18n keys dynamically without listing all possible keys somewhere static (breaks tooling)
- ❌ Hardcoded English alt text "for accessibility" — accessibility text is the most important to translate
